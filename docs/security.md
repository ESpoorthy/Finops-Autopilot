# FinOps Autopilot — Security & Safety Model

## 🛡️ Executive Security Summary

FinOps Autopilot enforces **Autonomy Within Policy Boundaries**.

To prevent dangerous or unintended autonomous actions, FinOps Autopilot strictly separates **autonomous recommendation and pull request generation** from **production deployment**. Autonomous Terraform apply operations are strictly forbidden. Every infrastructure patch generated by the agent must pass policy guardrail checks, staging validation in Cloud Build, and mandatory review and merge by a human engineer.

---

## 🔒 Safety Policy Guardrails

All optimization proposals are evaluated by the **Safety Agent (`agent/safety.py`)** prior to code modification:

| Guardrail Policy | Rule Description | Enforcement Action |
| :--- | :--- | :--- |
| **Protected Categories** | IAM permissions, KMS keys, Core Networking, DB instances, Encryption resources | `SAFETY_BLOCKED` — Execution terminates immediately |
| **Financial Impact Cap** | Maximum financial change threshold (`MAX_MONTHLY_CHANGE=1000.0`) | `SAFETY_BLOCKED` — Execution terminates if projected change exceeds threshold |
| **Minimum Confidence** | Minimum confidence score threshold (`MIN_CONFIDENCE=0.80`) | `SAFETY_BLOCKED` — Execution terminates if confidence < 80% |
| **Staging Validation** | Automated Cloud Build validation (`terraform fmt`, `validate`, `plan`, pytest) | Execution fails if staging validation returns `FAIL` |
| **Human Merge** | Production Terraform deployment | **Mandatory human engineer review & merge** |

## 🗝️ IAM & Credentials Security

1. **Least Privilege Service Account**:
   - `roles/monitoring.viewer` (Read-only Cloud Monitoring metrics)
   - `roles/bigquery.dataViewer` (Read-only BigQuery billing exports)
   - `roles/datastore.user` (Firestore read/write for run history)
   - `roles/cloudbuild.builds.editor` (Triggering Cloud Build validation)
2. **Secret Management**:
   - `GEMINI_API_KEY` and `GITHUB_TOKEN` are passed via environment variables or Secret Manager.
   - Zero secrets, API keys, or GCP service account credentials are stored or committed in source code repositories.
